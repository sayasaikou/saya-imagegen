# 角色 LoRA：数据集、配置与 16 GB 的边界

> 目标：让同一个角色在不同构图下保持一致。这是唯一能做到「1:1 复刻」的路线。

## 一、数据集怎么组

| 项 | 做法 |
| --- | --- |
| 张数 | 15–40 张，同一角色；少于 10 张容易过拟合背景 |
| 内容 | 正面/侧面/半身/全身各几张；表情与服装尽量同源 |
| 尺寸 | 长边 ≥1500 优先；统一裁到同一比例（如 832×1216） |
| 命名 | `<id>_<name>.png` + 同名 `.txt`（caption），一一对应 |
| 触发词 | 一个不常见的词（例：`zmdstyle`），写在每张 caption 开头 |

caption 模板（简单但够用）：

```
<trigger>, anime character illustration, full body, detailed lineart,
realistic lighting, intricate costume design
```

更好的做法：caption 只写「可变的」（姿势、视角、背景），角色固有特征交给触发词。否则角色特征会被稀释。

## 二、16 GB 能训什么

| 模型 | 训练档位 | 结论 |
| --- | --- | --- |
| Anima 2B | 很舒适 | 可训，首选 |
| SDXL 谱系（2.5B） | 很舒适 | 可训，工具最成熟 |
| FLUX.1 | 官方支持 16 GB（`--blocks_to_swap`） | 可训，慢 |
| Qwen-Image 20B 级 | 官方示例 24–32 GB | 不建议 |
| Krea 2 12.8B | 32 GB 内存加载就见底 | 不可行 |

**一个容易踩的判断错误**：显存够不等于能训。12.8B 模型加载 bf16 权重需要的内存超过 32 GB，进程会被系统杀掉——这不是 OOM 报错，是直接消失。

## 三、训练参数（保守起步）

| 参数 | 值 | 说明 |
| --- | --- | --- |
| 网络维度 / rank | 16–32 | 角色 LoRA 16 够；风格 LoRA 可以到 32–64 |
| 学习率 | 1e-4 量级 | 先低后高 |
| batch | 1–2 | 16 GB 不要贪 |
| 分辨率 | 与出图一致 | 训练 832×1216 就在 832×1216 出图 |
| 步数 | 按样本数 × 10–20 粗估 | 过拟合表现为「只会摆同一个姿势」 |
| 保存间隔 | 每 500 步 | 便利后挑最像的一档 |

## 四、验收：怎么判断训成了

1. **同 seed、同提示词，只换 LoRA 强度**（0 / 0.6 / 0.8 / 1.0），看身份是否随强度单调上升；
2. **换构图**（站/坐/背身），看是否还认得出；
3. **换场景与光位**，看服装细节是否漂；
4. 任一项失败，先看是过拟合还是欠拟合，不要靠加步数硬拉。

## 五、两阶段采样（Krea 2 专用思路，可迁移）

有些模型官方分两档：RAW（未蒸馏，多样性高，用来训 LoRA）与 Turbo（8 步，日常出图）。在 RAW 上训的 LoRA 可以直接用到 Turbo 上。

两阶段采样就是把一次去噪拆开：Stage 1 用 RAW 跑前段（构型好），Stage 2 用 Turbo 跑余下（快、质量高），交接点可调。这是「时间不是问题、质量优先」时的正解。

## 六、已知边界

- 训练集里如果有大量同背景/同光照图，LoRA 会把背景也学进去；要混入背景多样图。
- 非商用许可的底模（Anima 等）训出来的 LoRA 也受同类限制，交付前先看许可。
- 本仓不放数据集本体；上面的结构与 caption 格式足以重建。
